## Problems / Blockers

None hard-blocking. A few things worth flagging:

- `mockgal_galfit.py`'s Ferrer mu(0) inversion fix (`052d758`) is on
  this branch but **not yet on main**. The bug exists in `main` for
  any caller that uses `mockgal_galfit.render_with_galfit` on a
  `MockGalaxy` containing a `FerrerComponent`. Per user direction
  (this session), the fix will ride into main when the CS4G branch
  ships — no separate bug-fix branch needed unless the user changes
  their mind.
- libprofit's `profit-cli` requires `DYLD_LIBRARY_PATH` set to the
  build directory (`libprofit/build`) on this machine because the
  binary's @rpath is hardcoded to `/Users/mac/...`. mockgal does NOT
  set this automatically — callers must export it before `python ...`.
  `qa_libprofit_vs_galfit.py` sets it in-process via `os.environ`;
  any future scripts that need libprofit should follow that pattern
  or rely on the user's shell having it set.
- Two galaxies in the 198-sample have Sersic indices clamped at load
  time (ESO509-026 n=14.4 → 8.0, NGC3718 n=9.0 → 8.0). They are
  excluded from the P8.9 target set by design but worth remembering
  if anyone tries to render them later.

## Key Decisions

- **mockgal upgrade was merged to main only with explicit user blessing
  this time.** The user reminded me of the global rule "never merge to
  main without explicit approval." The local-only rewind + clean
  re-merge was performed earlier in this session.
- **Ferrer parameterization compatibility was empirically verified**:
  GALFIT's `ferrer` and `ferrer2` are mathematically identical (the
  "Surface brightness at FWHM" comment in S4G outgal files is
  misleading), and GALFIT's α/β map 1:1 to libprofit's a/b. This
  means our analytic SB→integrated-mag conversion is sound;
  empirically validated to 0.02% flux accuracy.
- **Ferrer SB→mag inversion belongs in `mockgal_galfit.py`, not in
  the FerrerComponent class.** FerrerComponent stores the integrated
  magnitude (consistent with SersicComponent's contract) and the
  GALFIT-side renderer takes responsibility for converting back to
  GALFIT's central-SB convention.
- **Model file is configuration-agnostic** (kpc + abs_mag, no pixel
  info) per the Huang2013 convention. The same
  `cs4g_sample_models.yaml` will support multiple manifest rows in
  the future (HSC-flavored production runs, deeper noise scenarios,
  etc.).
- **Single-component galaxies dropped from the sample** at the
  `--min-components 2` flag of `downsample.py`; this matches the
  user's "complex models" intent for CS4G.
- **Image sizing**: `size_factor=6` from the Huang2013 baseline produces
  ~2200×2200 px images at S4G native pixel scale for typical NGC1097-
  size galaxies. Within the `max_image_size=4001` cap. No tightening
  done; can revisit per-galaxy in P8.9 if the comparison FOV needs
  alignment with the IRSA `_subcomps.fits` cube extent.
