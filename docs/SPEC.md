## Mock-dataset folder contract

The isophote-fitting benchmark pipeline (Phase 10 and beyond) is designed
to consume **any** mock-galaxy dataset produced by `scripts/generate_mocks.py`
without knowing the name of the sample (Huang2013, CS4G/s4g_mock, future
samples, etc.). This section defines the folder layout every mock dataset
must follow.

### Layout

```
{dataset_root}/
├── run_manifest_original.yaml      # Verbatim copy of the input run manifest
├── run_manifest_resolved.yaml      # Per-row resolved ImageConfig values (defaults merged in)
├── run_metadata.json               # Timestamp, git branch, script path, resolved rows
└── {galaxy}/                       # One subdir per rendered galaxy
    ├── {galaxy}_{config_a}.fits
    ├── {galaxy}_{config_b}.fits
    ├── ...
    └── {galaxy}_mosaic.png         # QA mosaic of all configs rendered in the last run
```

- `{dataset_root}` is whatever path was passed to `scripts/generate_mocks.py --output`
  (e.g. `~/Dropbox/work/data/huang2013`, `~/Dropbox/work/data/s4g_mock`). The
  runner writes per-galaxy subdirs directly under this path — no sample-name
  subdir is injected between `--output` and `{galaxy}`.
- `{galaxy}` is the sanitised galaxy name from the model file (spaces removed
  via `mockgal.sanitize_filename`). Example: `"ESO 185-G054"` → `ESO185-G054`.
- `{config_name}` is the `name:` field of a row in the manifest's `configs:`
  list. The shared Huang2013+CS4G convention is `{depth}_z{redshift*100}`:
  - `clean_z005` — deep reference (single row, `sky_sb_limit=28.5`).
  - `wide_z{005,020,035,050}` — HSC wide depth × 4 mock redshifts.
  - `deep_z{005,020,035,050}` — HSC dud depth × 4 mock redshifts (in the
    Huang2013 and CS4G manifests; the config-name prefix is `deep` even
    though the manifest filename contains `dud`).

### Multi-manifest datasets

A single dataset directory can accumulate output from **multiple manifest
runs**. The Huang2013 and CS4G production workflows both run `{dataset}_wide`
and `{dataset}_dud` manifests in sequence against the same `--output` root:

- Per-galaxy FITS files from both runs coexist in the same `{galaxy}/`
  subdir (no collisions — the config names differ: `wide_z*` vs `deep_z*`).
- `run_manifest_original.yaml`, `run_manifest_resolved.yaml`, and
  `run_metadata.json` are **overwritten** by each run. Only the last run's
  metadata survives on disk. This is an explicit design choice: the
  benchmark pipeline does not need to reconstruct the historical manifest
  sequence; provenance for any single FITS file is recoverable from its
  header (config name, noise seed, engine, etc.).
- `{galaxy}_mosaic.png` is also overwritten; it shows only the configs
  from the last manifest. If a full 9-panel mosaic is ever needed, it
  should be generated by a downstream QA script reading the FITS files,
  not by the mockgal runner.

### Required FITS header keys

Every `{galaxy}_{config}.fits` file carries these keywords (written by
`mockgal.save_fits`):

- `PIXSCALE` (arcsec / pix)
- `ENGINE` (`libprofit`, `astropy`, or `auto`)
- `NOISE` (bool; true when `noise_enabled: true`)

Other header fields (zeropoint, PSF FWHM, noise seed, sky SB limit, etc.)
may or may not be present depending on the ImageConfig that produced the
FITS. Consumers that need these should prefer `run_manifest_resolved.yaml`
or `run_metadata.json` for authoritative values.

### Required metadata contents

`run_metadata.json` carries the per-run provenance the benchmark pipeline
can rely on:

```json
{
  "timestamp_utc":        "ISO-8601 string",
  "script_path":          "absolute path to scripts/generate_mocks.py",
  "git_branch":           "branch name or null",
  "source_manifest":      "relative path to inputs/.../runs/*.yaml",
  "run_name":             "e.g. cs4g_hsc_i_wide",
  "description":          "free text",
  "model_file":           "relative path to the model YAML",
  "output_root":          "informational; may be null",
  "selected_config_names": ["...", "..."] or null,
  "selected_galaxy_names": ["...", "..."] or null,
  "galaxy_count":          int,
  "config_count":          int,
  "expected_image_count":  int,
  "warnings":              ["..."],
  "resolved_rows": [
    {"name": "...", "redshift": float, "pixel_scale": float, ... full ImageConfig}
  ]
}
```

### Producing a conforming dataset

```
python scripts/generate_mocks.py \
    --run-manifest inputs/{sample}/runs/{sample}_hsc_i_wide.yaml \
    --output {dataset_root}

python scripts/generate_mocks.py \
    --run-manifest inputs/{sample}/runs/{sample}_hsc_i_dud.yaml \
    --output {dataset_root}
```

The runner is dataset-agnostic: any manifest pointing at any
`mockgal.load_model_file`-compatible YAML will produce a conforming dataset.

### Current conforming datasets

- `~/Dropbox/work/data/huang2013/` — 93 galaxies × 9 configs. Produced by
  `huang2013_full.sh` at the repo root.
- `~/Dropbox/work/data/s4g_mock/` — 198 galaxies × 9 configs. Produced by
  `s4g_mock_full.sh` at the repo root.

Any new sample should (a) add an `inputs/{sample}/` directory with its
model YAML and two HSC-i manifests, (b) add a `{sample}_full.sh` at the
repo root, and (c) use `~/Dropbox/work/data/{sample}/` as the dataset
root so everything stays parallel.
